## Why this slice comes before the method is cut

Slice 3 reduces `METHOD.md` to the rules an agent needs in every session. **That decision cannot be made
well without the evidence in front of you**: a rule with a measurement behind it and a rule that merely
sounds right are indistinguishable in the current document, and cutting on instinct would keep the
well-written rules rather than the well-founded ones.

So the evidence is assembled first, rule by rule. What survives into the core in slice 3 is then a
judgement made against a list rather than against memory.

**Keyed by rule, never by section number.** `METHOD.md`'s sections are about to be renumbered and
rewritten. An entry keyed to `§4` would be wrong within the week; an entry keyed to *plans are deleted
after execution* stays correct through any rewrite that keeps the rule.

## Constraints

- `SOURCES.md` is **read by a person reviewing the method, and by nobody else**. It is not injected, not
  loaded per session, and no skill points at it. Length is therefore not the constraint it is elsewhere;
  being findable and honest is.
- **Every entry states what was actually measured**, not what it supports. *"1,650 sessions; file size
  25–500 lines produced no detectable effect"* is a finding. *"Shorter files work better"* is a summary
  of somebody's opinion, and it is how a source becomes decoration.
- **A rule with no evidence says so.** Several rules here were learnt from incidents in this repository
  and have no paper behind them. Those are first-class and are marked as measured here, not dressed in a
  citation that does not fit. A rule with neither is marked as reasoned, so slice 3 can see it plainly.
- **Where the method departs from a source it cites, the entry says so and why.** This is the most
  valuable content in the document: a future reviewer meeting one of these will otherwise conclude the
  author misread the source.
- **`ROOT` is the repository root**, declared at the top of every check as exactly:

  ```js
  const path = require('path');
  const ROOT = path.join(__dirname, '..');
  ```

  It is not imported from anywhere. *(This was a GATE 2 finding on slice 1's plan as well as this one.
  Task 8 records it for slice 5, so the `plan` skill carries it and no future plan has to.)*
- Node's standard library only, for the check. No dependencies.

## Task 3 — `test/sources.js`

**Files:** `test/sources.js` (create)

`{ problems: string[], entries: number, byKind: { published: number, measuredHere: number, reasoned: number } }`.

hand and checked by reading is a document with a gap nobody finds.

**Steps:**

1. Parse `SOURCES.md`. For each `### ` heading under `## Rules and the evidence behind them`, require

   `yes` or `no`.

5. **Negative case:** a fixture under `os.tmpdir()` whose `SOURCES.md` contains one entry missing
   `Kind:`, one with an invalid kind, one `published` with no link, one `measured here` with a link,
   and one link written as `](…)`. Assert exactly five problems, each naming its entry, and assert the
   entry count is 5 first — a run that parsed nothing must not read as a pass.

**Verification:** `node test/sources.js` prints

**Files:** `SOURCES.md` (modify)

The most valuable content in the document. Each departure names the source, what it says, what this
method does instead, and why.

**Steps:**

1. Under `## Where this method departs from its sources`, write three entries, each with the fields
   `**Source says:**`, `**This method does:**`, `**Why:**`:
   - **Plans are deleted.** The superpowers `writing-plans` skill (#5), which this method takes its plan
